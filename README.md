# LOOP PLAY

SiBC·iCHMS·SH·대전팀이 [인바이츠루프 프로토타입 V5](https://claude.ai/artifact/2XZQo8NwGy6Bs4tqyojLfa)를 바탕으로 만든 게임 쇼케이스입니다. 처음 사용하는 분도 V5 사용법을 쉽고 재미있게 익힐 수 있도록 각자 게임을 만들었습니다.

## 실행

저장소를 내려받은 뒤 `index.html`을 브라우저에서 여세요. `games`, `images`, `app.js`, `games.js`를 함께 보관해야 합니다.

GitHub Pages를 사용하려면 저장소 **Settings → Pages → Build and deployment**에서 **Deploy from a branch → main → /(root)**를 선택합니다.

## 구성

- 4개 팀별 목록, 제작자별 복수 출품작 소개
- 실제 캡처 이미지, 게임 소개 및 조작법
- HTML 게임 28개와 외부 링크 게임 9개 (총 37개)
- 전체 37개 게임 월드컵: 무작위 64강 대진·27개 부전승·36번 선택, 되돌리기·기록 복원
- 이전에 시작한 SiBC 8개 게임 대진도 이어서 제출 가능
- 전체·팀별 누적 최종 선택 순위, 득표수·비율, 공동 순위

외부 게임은 인터넷 연결이 필요합니다. 일부 원본 게임의 확장 화면은 온라인 라이브러리를 참조합니다. 자세한 내용은 `사용안내.txt`를 참고하세요.

## 월드컵 결과

**현재 상태:** 로그인 없는 결과 제출을 활성화했습니다. 우승 화면의 **우승 결과 제출** 버튼으로 공용 결과를 저장할 수 있습니다. 닉네임은 선택이며, 미입력 시 익명으로 기록됩니다.

- 공용 결과 CSV: https://loop-play-results.devyks-com.chatgpt.site/results.csv
- 실시간 결과 요약: https://loop-play-results.devyks-com.chatgpt.site/
- GitHub 내 기록: [results/results.csv](results/results.csv)

공용 CSV에는 접수 번호, 닉네임, 우승 게임 ID·제목·제작자, 한국 시간 기준 제출 시각을 기록합니다. 닉네임과 결과는 공개됩니다. 전체 경기 기록은 서버에서 대진 검증에 사용합니다.

서버에서 같은 접수 번호와 동일 내용을 다시 제출하면 중복 저장하지 않습니다. 실패 시 우승 화면에서 다시 시도할 수 있습니다. 계정 없이 참여하므로 사람당 한 번만 참여했는지를 보장하지는 않습니다.

실제 연결 시에는 `submission.js`의 `RESULTS_ENABLED`를 `true`로 바꾸고, GitHub 저장소의 Actions 변수 `RESULTS_SYNC_ENABLED`를 `true`로 설정합니다. 현재 결과 제출과 자동 동기화가 활성화되어 있습니다.

활성화 후 GitHub Actions의 `Sync public tournament results`가 5분 주기로 공용 CSV를 저장소에 동기화합니다. GitHub의 실행 대기 상황에 따라 실제 반영은 더 늦을 수 있습니다. Actions에서 `Run workflow`로 수동 동기화할 수도 있습니다.

소개 페이지는 GitHub Pages에서 제공하고, 결과 저장 API와 CSV는 별도 Sites 서버에서 제공합니다. 결과를 제출하려면 인터넷 연결이 필요합니다.

## GitHub 즉시 기록 연결

관리자 전용 설정: https://loop-play-results.devyks-com.chatgpt.site/admin/github

서버 소유자가 위 화면에서 `ksyoo-hconnect/game` 저장소만 선택한 Fine-grained token(Contents 읽기·쓰기)을 한 번 연결하면, 이후 제출은 GitHub CSV 기록을 확인한 후 완료로 표시합니다. 키는 서버에서 암호화되어 저장되며 브라우저 코드나 GitHub 저장소에 포함하지 않습니다.

동시 제출로 파일 SHA가 바뀌면 최신 CSV와 병합하여 재시도합니다. 실패한 제출은 서버에 보관하고, 같은 결과를 다시 제출해도 득표가 중복되지 않습니다. 전용 키 연결 전까지는 기존 정기 동기화를 유지합니다.

## 누적 인기 순위

사이트의 **인기 순위** 메뉴에서 공용 결과에 기록된 최종 우승 횟수와 전체 제출 대비 비율을 확인할 수 있습니다. 첫 화면에도 최다 선택 게임을 표시합니다.

- 같은 득표수는 공동 순위로 표시하며, 0표 게임에는 순위를 부여하지 않습니다.
- 제출이 없으면 0건과 ‘아직 집계된 결과 없음’을 표시합니다.
- 중간 경기 선택 횟수와 개인 브라우저에만 남아 있는 미제출 결과는 합산하지 않습니다.
- 표시 중인 페이지는 5초마다 확인하며 새로고침 버튼으로 직접 갱신할 수 있습니다.
- 실시간 집계 API를 우선 읽으며, 연결 실패 시 공개 저장소의 raw CSV로 대체합니다. 즉시 기록 키 연결 후에는 제출 완료 응답으로 받은 집계도 즉시 화면에 반영합니다.
- 파일 로드 실패는 0표와 구분하며, 이미 불러온 결과가 있으면 마지막으로 확인한 값을 유지합니다.

집계 테스트: `node --test tests/ranking-data.test.cjs`

## 수정

- 첫 화면과 제작자 소개: `index.html`
- 게임 제목, 제작자, 설명 및 링크: `games.js`
- 대표 이미지: `images/`

실행 게임 원본을 보존했습니다. 대전팀 개인 출품작 소개 페이지의 잘못된 상대 링크만 수정했습니다. 게임의 소개·기획 자료는 별도 보조 링크로 제공하며 월드컵에 중복 등록하지 않습니다.

게임 추가 시 games.js, game-registry.json, result-service/lib/games.json을 함께 갱신하고 결과 서버도 배포해야 합니다. 부전승은 선택 횟수와 득표수에 포함하지 않습니다. 팀별 순위 비율은 해당 팀 게임의 최종 우승 표를 분모로 합니다. 기존 SiBC 투표와 신규 전체 대진 투표를 누적하므로 모든 게임이 같은 시점부터 표를 받은 것은 아닙니다.
